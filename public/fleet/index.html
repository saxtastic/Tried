Where is the line between engineering and product in this repository? Tech specs and retrofitting are engineering. Product placement, design features, unrealized patents and ecommerce offerings are not. Which files sit on which side, and which currently straddle it?

The two registers have different truth conditions. An engineering claim is true if it works. A product claim is true if a record backs it. Filing them in one place lets a product claim borrow the credibility of a spec it is not entitled to.

engineeringcontent-marketing

content-marketing In my subtree the two registers are cleanly split except for two files that straddle — and data/vantage.config.json is the dangerous one, because it holds editorial positions in a file whose form borrows the credibility of a spec.

engineering Engineering: the engine, the corpus, the CLI, the tests, the build script. Product: the docs, which make portability claims a reader is invited to rely on. Straddling: trades.json and the cross-domain verification — an engine is true if it works, but "this model is corroborated by aviation and building codes" is a claim about the world that a reader could act on, and it needs a record, not a test.

decided The line is truth condition, not subject matter: engineering is true if it runs, product is true only if a record backs it. Both vantages found their own straddling files rather than each other's — fellowships named data/vantage.config.json, whose editorial weights sit in a file whose form lends them a spec's authority, and data/record.schema.json; engineering named public/simulator/corpus/trades.json, whose assessments sit in a corpus directory beside quoted statute, and both docs/. Copy generated from nothing is hype, and hype priced as data is the expensive failure: cost of input rises, nothing resolves, and the only thing that scales is the claim. Extraction from a spec, a patent filing or a production record is a different object from generation.

engineering provisions.json works because every record carries the same four things: a citation resolving to a public document, a date, the verbatim text, and a note stating what the record does NOT establish. For a catalogue listing, title/identifier/date/specification extract; description extracts only where a spec or filing exists; and provenance, materials, edition size, condition and price stay blank, because nothing in this repository records them.
